# agentic-rules リポジトリ設計

## 目的

AI コーディングエージェントに与える「ルール」(設計原則、テスト規律、コミット規約といった
規範文書)を、このリポジトリ 1 箇所に集約し、複数のプロジェクト・複数のエージェントへ
配布可能にする。ルールの形式は Agent Skills 仕様(agentskills.io。SKILL.md という
説明付き指示書をディレクトリ単位で配布する公開規格)に準拠する。

## 役割分担

| 場所 | 持つもの |
|---|---|
| agentic-rules(本リポジトリ) | ドメインルール(スキル形式) |
| claude-skills リポジトリ | ワークフロー(手順・自動化) |
| dotfiles | 個人環境固有の設定(対話規範、モデル振り分け、CLI ツールガイド) |

ルールからワークフローへの依存は禁止。ワークフローからルールへは
「スキル名 + 対応バージョン範囲」の宣言でのみ依存する(本文の複製・パス参照はしない)。

## 配布と更新

導入経路は 3 型を提供する。リポジトリを `skills/<スキル名>/SKILL.md` レイアウトにし、
配布用メタデータを置くことで全経路に対応する。

1. **plugin 型**(導入時の設定のまま更新が届く。個人環境向け):
   - Claude Code plugin marketplace(`.claude-plugin/marketplace.json`)。
     `plugins[0].version` を宣言しているため、更新は commit 追従ではなく
     この版が上がったときに配信される
   - Codex CLI plugin(同じ `.claude-plugin/` の manifest を読む)
   - OpenCode plugin(`package.json` + `.opencode/plugins/` の config hook で
     スキルパスを登録する。セッションへの注入は行わない — 常時適用ルールの
     配達は scaffold が生成する AGENTS.md に一本化する)
2. **copy 型**(gh skill / npx skills — GitHub リポジトリからスキルを取り込む CLI 群):
   導入時にコピーされ、更新は明示的なコマンド実行で取り込む。バージョン固定ができるため
   プロジェクト・チーム・CI 向け
3. **package-manager 型**(APM — microsoft/apm): apm.yml で複数エージェントの設定を
   一括管理する利用者向け。リポジトリ側の追加物はなく、`.claude-plugin/plugin.json` を
   持つリポジトリを plugin collection として解決し `skills/` を自動検出する。利用側は
   apm.yml の参照(タグ/SHA)で版を固定し、lockfile が解決結果を記録する。更新は利用側の
   `apm update` で取り込む

OpenCode 用の `package.json` は配布用 manifest であり、公開 npm パッケージではない
(`private: true` で誤公開を防ぐ)。

バージョンの正本(canonical)は `.claude-plugin/marketplace.json` の
`plugins[0].version` とする。他の manifest(plugin.json / package.json)の version と
CHANGELOG の最新リリース見出しは canonical との一致をバリデータが機械検証する。

canonical は版の表示であると同時に、plugin 型の更新が配信される条件でもある。
リリース規律として、利用者に見える変更(ルール本文・スキル構成・導入手順の変更)を
入れるときは必ず canonical を bump する。canonical を据え置いたままの変更は、
plugin 型で導入した利用者には届かない。

入手方法と再現性ポリシーは別物として扱う。リポジトリ側の義務は「リリースにタグを打つ」
「後方互換のない変更(ルールの意味が変わる変更)を区別して changelog に残す」まで。
同一プロジェクト内での版一致は現段階(ソロ運用)では保証せず、チーム利用時はタグ固定を
必須とする。
リリースのタグは `v{version}` 形式で打つ(例: 初回リリースは v0.1.0)。

## 命名規約

スキル名は `ba0918-<ドメイン名詞>`(例: `ba0918-commit`)。`ba0918` は所有者のユーザー ID で、
衝突回避専用の恒久プレフィックスとして扱い、変更しない。ドメイン名詞は短い一般語 1〜2 語。
名前は仕様の制約(64 文字以内・小文字英数字とハイフン・ディレクトリ名と一致)に従う。

## スキル自己完結の原則

スキルディレクトリが唯一の配布単位である。

- 配布物の外を指すパス参照(`../shared/` など)は禁止。単体インストールで壊れるため
- スキル内部の `references/` への相対参照は許可
- 他スキルへの言及は「名前参照」のみ。入っていない環境でも壊れず、単に読まれないだけ
- 規則の複製は許容する。自己完結性を重複排除より上位の原則とする。共有原典への依存は、
  原典 1 箇所の変更が全参照スキルへ無審査で波及する事故を招くため
  (先行リポジトリ claude-skills で共有文書 1 変更が 10 スキルに影響した実害が根拠)
- 共有原典 + ビルド時埋め込みへの移行は自動発動しない。段階を踏む:
  複製間のドリフト(同じ規則の文言差が挙動差を生む等)が実害を出したら、
  まずバリデータに複製間の同期検査を追加する。それでも保守が破綻したときに限り、
  共有原典方式を改めて判断する

## 執筆スタイル

- 本文は英語。発火(エージェントがスキルを読み込む判断)を担う description は
  英語 + 日本語キーワード併記
- 一律の短文化はしない。ルールの種類で文体を選ぶ:
  禁止・必須 → 1 行 1 命令 / 状況依存の判断 → 理由と適用条件 /
  誤解されやすい境界 → Good/Bad 対比例 / 完了判定 → 証拠要求チェックリスト
- 確認ゲートは「〜を確認したか?」の自己問答ではなく、テスト出力・検索結果・diff といった
  観測可能な証拠を要求する形で書く
- 各スキルの構成順: 適用条件 → 必須ルール → 判断基準と例外 → 最小限の対比例 → 完了時の証拠
- SKILL.md は 500 行以内

## 手続き型スキルの実行条件

ファイルを書くなどの副作用を持つ手続き型スキル(例: `ba0918-scaffold`)は、その作業自体への
ユーザーの明示的な依頼があるときだけ実行する。他の作業の副産物として自動実行しない。
description による発火(候補としてスキルが読み込まれること)と、副作用の実行許可は
別物として扱い、手続き型スキルは本文と description の両方にこの条件を明記する。

## AGENTS.md と PROJECT.md

利用側プロジェクトの AGENTS.md(エージェントが常時読む指示ファイル)は薄いルーターに徹する。
常時適用・工程必須の基礎ルールへの参照表(ルーティング表)だけを持ち、プロジェクト固有の
文脈は PROJECT.md に分離する。ルーティング表は手書きせず、`ba0918-scaffold` スキルが
インストール済みルールスキルのメタデータから生成する。

## 初期スキル

| スキル | 内容 | 種 |
|---|---|---|
| ba0918-design | 設計原則(テスタビリティ最上位)・置換可能性の規則(詳細仕様: replaceability-rule.md) | 既存文書の移植 + 追記 |
| ba0918-placement | 情報配置(コード/テスト/コミット/コメントの四象限) | 既存文書の移植 |
| ba0918-tdd | テスト先行開発の契約 | 既存文書の移植 |
| ba0918-testing | テストのアンチパターン | 既存文書の移植 |
| ba0918-commit | コミット規約 | 既存文書の移植 |
| ba0918-secrets | 機密情報の扱い・機密文脈(内部識別子・機密文書・第三者著作物)の公開先への露出防止 | 新規(スコープ: 検出・ステージング禁止・露出防止・宛先境界) |
| ba0918-scaffold | AGENTS.md / PROJECT.md / CLAUDE.md シム(`@AGENTS.md` 1 行)の生成 | 新規(メタスキル) |
| ba0918-release | リリース規律(canonical version・bump・タグ・changelog) | 運用実績の蒸留 |
| ba0918-delegation | 委譲規範(orchestrator 原則・役割契約 5 種・executor table) | 運用実績の蒸留 |
| ba0918-verification | 検証規範(証拠要求・worst-of 集約・受け渡し衛生) | 運用実績の蒸留 |
| ba0918-reuse | 再利用判断(層分解・8 段探索梯子・採用/自作の記録) | 新規(詳細仕様: reuse-rule.md) |

dependencies / review / 言語別ルールは、必要が実際に発生した時点で追加する
(changelog 系は ba0918-release として追加済み — 延期トリガー「必要の実発生」の発火による)。
ここでの review はコードレビュー規約の領域を指す。検証規範 ba0918-verification
(routing の `required:review`)は別領域であり、この延期項目を消費しない。
